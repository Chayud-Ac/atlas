# M3: Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the user has chosen inline execution) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@atlas/web`, a React app that signs in, loads its settings from a runtime `/config.json`, shows the signed-in user from `GET /api/users/me` and lets them create, list and delete notes. Component tests use React Testing Library and MSW, and the app runs locally against the M2 API.

**Architecture:**

- **Startup** (`main.tsx`):
  1. Fetch `/config.json`.
  2. Validate it with zod.
  3. Create the `Auth` implementation.
  4. Render `<App auth={auth} />`.

  One build therefore runs in every environment.

- **`Auth` is an app-owned interface** (`isSignedIn`, `signIn`, `signOut`, `getAccessToken`) with two implementations:
  - `msal-auth.ts`: Entra ID through `@azure/msal-browser` redirects
  - `mock-auth.ts`: the local mock OIDC server

  Components and tests use only the interface, and tests pass a fake.

- **Data:** `api.ts` holds the `fetch` wrapper:
  - adds the bearer token
  - validates responses with the shared zod schemas
  - turns problem+json into an `ApiError`
  - starts sign-in again after a 401

  Each feature has `<feature>.api.ts` (TanStack Query hooks) and `<feature>.page.tsx` or another component file.

- **The browser only talks to its own origin:**
  - Vite proxies `/api` to the API in dev.
  - nginx does the same in the container (M4).

  So the API needs no CORS.

**Spec:** `docs/specs/2026-10-13-atlas-scaffold-design.md`, sections §6.3 (web sign-in), §10 (web) and §14.1 (web tests).

**Checked against the installed packages, not from memory:**

- **MSW 3** keeps `setupServer`, `http`, `HttpResponse`, `server.use` and `resetHandlers`, but `listen({ onUnhandledRequest })` became `listen({ onUnhandledFrame })`.
- **MSAL v5:**
  - `createStandardPublicClientApplication(config)` creates and initializes the client.
  - `protocolMode` moved from `auth` to `system`.
  - `navigateToLoginRequestUrl` is gone.
- **MSAL refuses any authority that isn't `https:`, `localhost` included** (`authority_uri_insecure`, in `UrlString.validateAsUri`). Our mock issuer is `http://localhost:8090/atlas`, so MSAL can't sign in against it.
- **The mock server's token endpoint** accepts `client_credentials` from the browser:
  - It answers CORS for `http://localhost:5173`.
  - It needs some `client_secret` (any value works).
  - It returns an access token with `iss`, `aud`, `scp`, `oid`, `tid` and `name` exactly as the API expects.

**Deviations from the spec (all deliberate; recorded in ADR 0007 and spec v2.3):**

1. **Local and CI sign-in uses `mock-auth.ts`, not MSAL in `protocolMode: OIDC`.** This is the spec's own fallback (§18 risks), and it becomes the plan because of the https rule above. `/config.json` gets `auth.kind: "msal" | "mock"`, and the config schema refuses `mock` unless `env` is `local` or `ci`. The API's issuer guard is still the real protection.
2. **`protocolMode` and `knownAuthorities` leave `/config.json`.** They only existed for the mock, so the web container variables `AUTH_PROTOCOL_MODE` / `AUTH_KNOWN_AUTHORITIES` become `AUTH_KIND`.
3. **No `@azure/msal-react`.** Sign-in and sign-out are redirects, so the signed-in state is known once at startup and never changes without a page load. msal-react's reactive state, event wiring and templates would add a dependency and nothing else. Our `Auth` interface covers the rest.
4. **`useAuth()` exposes `isSignedIn` instead of `user`.** The header shows the name from `GET /api/users/me`, as §10 says, so the token's copy of the name isn't needed.
5. **In Vite dev, `/config.json` is a git-ignored copy of `apps/web/config.example.json`** in `public/`, not a file generated by `npm run dev:config`. Copying it is the same habit as `.env.example` and needs no script.
6. **`traceparent` propagation and App Insights move to M7,** where the browser SDK adds them.
7. **The 401 handler signs in again at most once a minute.** If a fresh token is rejected too (say, a wrong audience), the app shows the error instead of redirecting forever.

- [ ] **Step 3: Implement.** `apps/web/src/config.ts`:

```ts
import { z } from 'zod';

/** How the app signs users in. Every value here is a public identifier. */
export const AuthSettings = z.object({
  /** `msal`: Entra ID. `mock`: the local mock OIDC server (ADR 0007). */
  kind: z.enum(['msal', 'mock']),
  authority: z.url(),
  clientId: z.string().min(1),
  /** The API's delegated scope, e.g. `api://<api-client-id>/access_as_user`. */
  apiScope: z.string().min(1),
});
export type AuthSettings = z.infer<typeof AuthSettings>;

/**
 * The shape of /config.json. The container writes it at startup from environment
 * variables, so one build runs in every environment (spec §10, ADR 0007).
 */
export const RuntimeConfig = z
  .object({
    env: z.enum(['local', 'ci', 'dev', 'uat', 'prod']),
    auth: AuthSettings,
  })
  // Same idea as the API's issuer guard: the mock is for local and CI only.
  .refine((config) => config.auth.kind === 'msal' || ['local', 'ci'].includes(config.env), {
    message: 'Mock sign-in is only allowed when env is local or ci',
    path: ['auth', 'kind'],
  })
  .refine((config) => config.auth.kind === 'mock' || config.auth.authority.startsWith('https://'), {
    message: 'MSAL needs an https authority',
    path: ['auth', 'authority'],
  });
export type RuntimeConfig = z.infer<typeof RuntimeConfig>;

export class ConfigError extends Error {
  override readonly name = 'ConfigError';
}

export async function loadRuntimeConfig(): Promise<RuntimeConfig> {
  // no-store: a redeploy can change the config without changing the URL.
  const response = await fetch(new URL('/config.json', window.location.origin), {
    cache: 'no-store',
  });
  if (!response.ok) throw new ConfigError(`GET /config.json returned ${response.status}`);
  const parsed = RuntimeConfig.safeParse(await response.json().catch(() => undefined));
  if (!parsed.success) {
    throw new ConfigError(`Invalid /config.json:\n${z.prettifyError(parsed.error)}`);
  }
  return parsed.data;
}
```

`fetch` gets an absolute URL because Node's `fetch` (used under jsdom) can't resolve a relative one.

- [ ] **Step 1: The interface.** `apps/web/src/auth/auth.ts`:

```ts
import { createContext, use } from 'react';

/**
 * What the app needs from sign-in. Components and tests use this, never MSAL,
 * so the identity provider can change without touching them (spec §6.3).
 * Members are function-valued properties, so they can be passed around unbound.
 */
export interface Auth {
  /** Known at startup: signing in and out both leave the page and come back. */
  readonly isSignedIn: boolean;
  readonly signIn: () => Promise<void>;
  readonly signOut: () => Promise<void>;
  /** A bearer token for the API. Starts sign-in again when none can be had silently. */
  readonly getAccessToken: () => Promise<string>;
}

export const AuthContext = createContext<Auth | null>(null);

export function useAuth(): Auth {
  const auth = use(AuthContext);
  if (!auth) throw new Error('useAuth() must be used inside <AuthContext value={auth}>');
  return auth;
}

/**
 * Returned while the browser leaves the page to sign in. It never settles,
 * so nothing renders an error in the moment before the page unloads.
 */
export function untilNavigation(): Promise<never> {
  return new Promise<never>(() => undefined);
}
```

import { z } from 'zod';
import type { AuthSettings } from '../config.js';
import { type Auth, untilNavigation } from './auth.js';

const STORAGE_KEY = 'atlas.mock-token';
/** Renew a minute early, so a token never expires between reading it and using it. */
const EXPIRY_MARGIN_MS = 60_000;

const TokenResponse = z.object({
  access_token: z.string().min(1),
  expires_in: z.number().positive(),
});
const StoredToken = z.object({ accessToken: z.string(), expiresAt: z.number() });

export interface MockAuthDeps {
  storage: Storage;
  reload: () => void;
  now: () => number;
}

/**
 * Sign-in for `env` local and ci, against the mock OIDC server in compose.yaml.
 * MSAL refuses non-https authorities, so this asks the mock's token endpoint
 * directly. The API still validates every token, and its issuer guard rejects
 * the mock issuer in dev, uat and prod (ADR 0007).
 */
export function createMockAuth(settings: AuthSettings, deps: MockAuthDeps = browserDeps()): Auth {
  const { storage, reload, now } = deps;

  function storedToken(): string | null {
    try {
      const stored = StoredToken.parse(JSON.parse(storage.getItem(STORAGE_KEY) ?? ''));
      return stored.expiresAt > now() ? stored.accessToken : null;
    } catch {
      return null;
    }
  }

  async function signIn(): Promise<void> {
    const response = await fetch(`${settings.authority.replace(/\/$/, '')}/token`, {
      method: 'POST',
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: settings.clientId,
        client_secret: 'not-a-secret', // the mock requires one and accepts any value
        scope: settings.apiScope,
      }),
    });
    if (!response.ok) throw new Error(`Mock sign-in failed with ${response.status}`);
    const token = TokenResponse.parse(await response.json());
    const expiresAt = now() + token.expires_in * 1000 - EXPIRY_MARGIN_MS;
    storage.setItem(STORAGE_KEY, JSON.stringify({ accessToken: token.access_token, expiresAt }));
    reload();
  }

  return {
    isSignedIn: storedToken() !== null,
    signIn,
    signOut: () => {
      storage.removeItem(STORAGE_KEY);
      reload();
      return Promise.resolve();
    },
    getAccessToken: async () => {
      const token = storedToken();
      if (token) return token;
      await signIn();
      return untilNavigation();
    },
  };
}

function browserDeps(): MockAuthDeps {
  return {
    storage: sessionStorage,
    reload: () => {
      window.location.reload();
    },
    now: () => Date.now(),
  };
}

import {
  createStandardPublicClientApplication,
  InteractionRequiredAuthError,
  type IPublicClientApplication,
} from '@azure/msal-browser';
import type { AuthSettings } from '../config.js';
import { type Auth, untilNavigation } from './auth.js';

/** The part of MSAL this app uses. Tests pass a fake with just these. */
export type MsalClient = Pick<
  IPublicClientApplication,
  | 'handleRedirectPromise'
  | 'getAllAccounts'
  | 'setActiveAccount'
  | 'loginRedirect'
  | 'logoutRedirect'
  | 'acquireTokenSilent'
  | 'acquireTokenRedirect'
>;

/**
 * MSAL for Entra ID. Redirects come back to the site root, which is what the
 * atlas-{env}-web registration lists (spec §6.3). Tokens are cached in
 * sessionStorage (MSAL's default), so they're gone when the tab closes.
 */
export function createMsalClient(settings: AuthSettings): Promise<IPublicClientApplication> {
  return createStandardPublicClientApplication({
    auth: {
      clientId: settings.clientId,
      authority: settings.authority,
      redirectUri: window.location.origin,
      postLogoutRedirectUri: window.location.origin,
    },
  });
}

/**
 * Sign-in with Entra ID through redirects. Call once at startup: it completes a
 * redirect that just brought the browser back, then reports who is signed in.
 */
export async function createMsalAuth(msal: MsalClient, apiScope: string): Promise<Auth> {
  const result = await msal.handleRedirectPromise();
  const account = result?.account ?? msal.getAllAccounts()[0] ?? null;
  msal.setActiveAccount(account);
  const scopes = [apiScope];

  async function signIn(): Promise<void> {
    await msal.loginRedirect({ scopes });
  }

  return {
    isSignedIn: account !== null,
    signIn,
    signOut: async () => {
      await msal.logoutRedirect({ account });
    },
    getAccessToken: async () => {
      if (!account) {
        await signIn();
        return untilNavigation();
      }
      try {
        // From MSAL's cache, renewed silently with the refresh token when it nears expiry.
        const { accessToken } = await msal.acquireTokenSilent({ scopes, account });
        return accessToken;
      } catch (error) {
        // The user must act: the session expired, or conditional access wants MFA.
        if (!(error instanceof InteractionRequiredAuthError)) throw error;
        await msal.acquireTokenRedirect({ scopes, account });
        return untilNavigation();
      }
    },
  };
}

import { Problem } from '@atlas/shared';
import { useMemo } from 'react';
import type { z } from 'zod';
import { type Auth, untilNavigation, useAuth } from './auth/auth.js';

/** A non-2xx API response, with its RFC 9457 problem body. */
export class ApiError extends Error {
  override readonly name = 'ApiError';
  readonly problem: Problem;

  constructor(problem: Problem) {
    super(problem.detail ?? problem.title);
    this.problem = problem;
  }

  get status(): number {
    return this.problem.status;
  }
}

export interface ApiClient {
  get: <T>(path: string, schema: z.ZodType<T>) => Promise<T>;
  post: <T>(path: string, body: unknown, schema: z.ZodType<T>) => Promise<T>;
  delete: (path: string) => Promise<void>;
}

const REAUTH_KEY = 'atlas.reauth-at';
const REAUTH_INTERVAL_MS = 60_000;

/** Calls the API on this origin. Every response is checked against its shared zod schema. */
export function createApiClient(auth: Pick<Auth, 'getAccessToken' | 'signIn'>): ApiClient {
  async function send(method: string, path: string, body?: unknown): Promise<Response> {
    const headers = new Headers({
      accept: 'application/json',
      authorization: `Bearer ${await auth.getAccessToken()}`,
    });
    if (body !== undefined) headers.set('content-type', 'application/json');

    const response = await fetch(new URL(path, window.location.origin), {
      method,
      headers,
      body: body === undefined ? undefined : JSON.stringify(body),
    });
    if (response.ok) return response;

    const problem = await readProblem(response);
    // 401: the API rejected our token, so sign in again.
    if (response.status === 401 && claimReauth()) {
      await auth.signIn();
      return untilNavigation();
    }
    throw new ApiError(problem);
  }

  return {
    get: async (path, schema) => schema.parse(await (await send('GET', path)).json()),
    post: async (path, body, schema) => schema.parse(await (await send('POST', path, body)).json()),
    delete: async (path) => {
      await send('DELETE', path);
    },
  };
}

/** The API client for the signed-in user. */
export function useApi(): ApiClient {
  const auth = useAuth();
  return useMemo(() => createApiClient(auth), [auth]);
}

/**
 * At most one sign-in retry a minute. If a fresh token is rejected too (say, the
 * API expects another audience), the error is shown instead of redirecting forever.
 */
function claimReauth(): boolean {
  const last = Number(sessionStorage.getItem(REAUTH_KEY) ?? 0);
  if (Date.now() - last < REAUTH_INTERVAL_MS) return false;
  sessionStorage.setItem(REAUTH_KEY, String(Date.now()));
  return true;
}

async function readProblem(response: Response): Promise<Problem> {
  const parsed = Problem.safeParse(await response.json().catch(() => undefined));
  if (parsed.success) return parsed.data;
  // A proxy or gateway error page: keep the status, not the body.
  return {
    type: 'about:blank',
    title: response.statusText || 'Request failed',
    status: response.status,
  };
}

      </header>

function createQueryClient(): QueryClient {

      queries: {
        // Retry network and server errors, not 4xx: asking again won't change a 403 or 404.

import { type CreateNoteInput, Note } from '@atlas/shared';
import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { z } from 'zod';
import { useApi } from '../api.js';

const NOTES_KEY = ['notes'];
const NoteList = z.array(Note);

export function useNotes() {
  const api = useApi();
  return useQuery({ queryKey: NOTES_KEY, queryFn: () => api.get('/api/notes', NoteList) });
}

export function useCreateNote() {
  const api = useApi();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (input: CreateNoteInput) => api.post('/api/notes', input, Note),
    // Refetch rather than patch the cache: the server decides order and timestamps.
    onSuccess: () => queryClient.invalidateQueries({ queryKey: NOTES_KEY }),
  });
}

export function useDeleteNote() {
  const api = useApi();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (id: string) => api.delete(`/api/notes/${encodeURIComponent(id)}`),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: NOTES_KEY }),
  });
}

function CreateNoteForm() {
  const styles = useStyles();
  const createNote = useCreateNote();
  const [title, setTitle] = useState('');
  const [body, setBody] = useState('');
  const [fieldErrors, setFieldErrors] = useState<FieldErrors>({});

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    createNote.reset();
    // The schema the API validates with, so most mistakes never leave the browser.
    const parsed = CreateNoteInput.safeParse({ title, body });
    if (!parsed.success) {
      const { fieldErrors: errors } = z.flattenError(parsed.error);
      setFieldErrors({ title: errors.title?.[0], body: errors.body?.[0] });
      return;
    }
    setFieldErrors({});
    createNote.mutate(parsed.data, {
      onSuccess: () => {
        setTitle('');
        setBody('');
      },
      onError: (error) => {
        if (error instanceof ApiError) setFieldErrors(fieldErrorsFrom(error));
      },
    });
  }

  const hasFieldErrors = Object.values(fieldErrors).some(Boolean);
  return (
    <form className={styles.form} onSubmit={handleSubmit} noValidate>
      <Field label="Title" required validationMessage={fieldErrors.title}>
        <Input
          value={title}
          onChange={(_, data) => {
            setTitle(data.value);
          }}
        />
      </Field>
      <Field label="Body" validationMessage={fieldErrors.body}>
        <Textarea
          value={body}
          onChange={(_, data) => {
            setBody(data.value);
          }}
        />
      </Field>
      {createNote.isError && !hasFieldErrors && <ErrorMessage error={createNote.error} />}
      <div>
        <Button type="submit" appearance="primary" disabled={createNote.isPending}>
          Add note
        </Button>
      </div>
    </form>
  );
}

/** Field errors from a 400 problem, keyed by the fields this form has. */
function fieldErrorsFrom(error: ApiError): FieldErrors {
  const errors: FieldErrors = {};
  for (const { path, message } of error.problem.errors ?? []) {
    if (path === 'title' || path === 'body') errors[path] ??= message;
  }
  return errors;
}

function NoteList() {
  const styles = useStyles();
  const notes = useNotes();
  const deleteNote = useDeleteNote();

  if (notes.isPending) return <Spinner label="Loading notes" />;
  if (notes.isError) return <ErrorMessage error={notes.error} />;
  if (notes.data.length === 0) return <Text>No notes yet.</Text>;

  return (
    <>
      {deleteNote.isError && <ErrorMessage error={deleteNote.error} />}
      <ul className={styles.list} aria-label="Notes">
        {notes.data.map((note) => (
          <li key={note.id}>
            <NoteCard
              note={note}
              deleting={deleteNote.isPending && deleteNote.variables === note.id}
              onDelete={() => {
                deleteNote.mutate(note.id);
              }}
            />
          </li>
        ))}
      </ul>
    </>
  );
}

          >
            Delete
          </Button>
        }
      />
      {note.body && <Text className={styles.body}>{note.body}</Text>}
    </Card>
  );
}

## Execution notes (2026-10-13)

What happened when the plan met the real packages:

1. **`tsc --build` accepted `apps/web` with `noEmit`** and `composite: false` as a reference of the root solution config. Probes confirmed that typecheck and the React lint rules really cover web files: a planted type error, a conditional hook and a hook exported from a component file were all caught.
2. **MSW 3 hands handlers a rebuilt `Request` whose `cache` reads `'default'`,** even when `fetch` was called with `cache: 'no-store'`. Its `FetchRequest` forwards `init`, so the loss is deeper in MSW. The config test now spies on `fetch` and asserts the arguments our code sends. `restoreMocks: true` is on, so spies never leak between tests.
3. **MSAL v5's `InteractionRequiredAuthError` constructor needs `(errorCode, correlationId)`.** The tests passed but `tsc` failed. That's a reminder that Vitest strips types without checking them, which is why `check` runs `typecheck` separately. The `AccountInfo` fixture is a full, correctly typed object instead of a cast.
4. **`@types/react` 19.3 deprecates `FormEvent`** ("FormEvent doesn't actually exist"). The form handler uses `SubmitEvent<HTMLFormElement>`.
5. **jsdom has no `ResizeObserver`,** which Fluent's `MessageBar` uses. `src/test/setup.ts` stubs it with `vi.stubGlobal`, as Fluent recommends for jsdom.
6. **`vite build` warned about one 767 kB chunk (213 kB gzip).** It's now split with Rolldown `codeSplitting` groups, so library chunks stay cached across deploys. The total is unchanged:

   | Chunk    | gzip    |
   | -------- | ------- |
   | App code | 3.2 kB  |
   | `vendor` | 33.5 kB |
   | `fluent` | 44.6 kB |
   | `msal`   | 63.6 kB |
   | `react`  | 68.3 kB |

7. **One extra test** covers mock sign-in renewing an expired token mid-session, which the coverage report showed as a gap. Web: 44 tests, 97% line coverage (reported only).
8. **The local run worked through the Vite proxy with a mock token:** `/config.json`, a 401 without a token, `/api/users/me` returning "Local Developer", and note create, list and delete.
