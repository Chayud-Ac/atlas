# M4b: End-to-End Tests Implementation Plan

> **How this plan is executed:** Claude explains each task and writes the files; the user reviews every change in the approval prompt and makes the commits (or asks Claude to). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Playwright tests that use the real app in a real browser, against the production images from M4a, run locally with one command and in CI on every pull request. Any Content-Security-Policy violation fails a test.

**Architecture:**

- **A new workspace, `tests/e2e` (`@atlas/e2e`).** Playwright drives Chromium against the compose `full` stack on http://localhost:8080. The stack isn't started by Playwright: it's the same stack used for manual testing, started with `docker compose --profile full up -d --build --wait`. CI starts it as its own step.
- **Two test users in the mock OIDC server,** picked by the token request's `client_id`:
  - `atlas-e2e-second-user` gets "Second User"
  - anything else gets "Local Developer", as today
- **A test becomes the second user** by changing `auth.clientId` in `/config.json` for its browser context (a Playwright route). The app's own sign-in button does the rest, so no test-only code ships in the app.
- **A shared fixture** (`src/fixtures.ts`) records `securitypolicyviolation` events in every page and fails the test if there were any.
- **zod's startup `eval` probe is switched off** (`z.config({ jitless: true })`), in a module that `main.tsx` imports first. M4a left this open.
- **CI's new `e2e` job** starts the stack, installs Chromium, runs the tests, and uploads the HTML report when they fail.

**Tech stack:** `@playwright/test` 1.64.0. 1.64.1 is 3 days old; taking a release that has been out about a week is a cheap supply-chain safeguard, and Dependabot proposes the next one. Plus Chromium (Playwright's build) and `actions/upload-artifact@v7`.

**Spec:** `docs/specs/2026-10-13-atlas-scaffold-design.md`, milestone M4 (§20), second half: §14.3 (E2E scenarios), §15 (`e2e` job), ADR 0009 from §17.

**Deviations from the spec (all deliberate):**

1. **How the second user signs in.** The spec doesn't say. This plan adds a `client_id` mapping in the mock and a `/config.json` override in the test (ADR 0009). The rejected alternatives:
   - a "sign in as…" picker, which would ship test-only code
   - a second issuer, which the API would reject
   - the mock's login form, which would need a different sign-in flow
2. **Tests also fail on CSP violations.** This isn't in the spec. It catches an app change that the CSP would break in production, and it's why the zod fix lands here.
3. **Playwright runs on the host and the CI runner, not in a container.** The browser then uses the same addresses as a developer, so the issuer from M4a matches. Playwright's container is for screenshot comparisons, which we don't do.
4. **CI doesn't cache the browser,** following Playwright's own advice: restoring a cache takes about as long as downloading, and the system packages can't be cached.
5. **The `e2e` job builds the images itself** with compose, rather than sharing `build-images`' cache. It's simpler, and costs about 2–3 minutes per run. Sharing the cache (for example with `docker/bake-action`) is a later optimisation.

**Verified before writing this plan** (scratch copy of `main` at `a143a73`, compose project `atlasproto` on ports 18080/18090):

- **The mock:** with the second-user mapping listed first, `client_id=atlas-e2e-second-user` gets "Second User" (`oid` `3333…`), and `atlas-web` still gets "Local Developer". The first matching mapping wins.
- **`npm install -D @playwright/test@1.64.0 -w @atlas/e2e` only links a brand-new workspace,** it doesn't install the package. Running a plain `npm install` first registers the workspace, then the package installs.
- **The new workspace type-checks and passes strict ESLint once its tsconfig adds the `dom` lib.** The CSP listener runs inside the browser, so it uses `document` and `window`.
- **Red, before the zod fix:** the 3 browser tests failed only on the CSP fixture (`script-src blocked eval`), and the API test passed.
  - The tests' own steps all passed, including the second-user override.
  - Contexts made with `browser.newContext()` inherit `baseURL`.
- **Green, after the fix:**
  - 4 of 4 tests pass.
  - With `CI=1 --repeat-each=5`, 20 of 20 pass with no retries.
  - The 44 web unit tests still pass.
- **The `e2e` job** passes actionlint and Prettier. Its first real run is on the PR.

**Conventions for every task:**

- Branch `feat/m4b-e2e`, from `main` at `a143a73` or later. Run every command from the repo root.
- Docker Desktop must be running, and the M4a stack too: `docker compose --profile full up -d --wait` if it isn't.
- The web image must be built from `main`, without the zod fix, for Task 3's red run. `docker compose --profile full build` refreshes it.

- [ ] **Step 1: Create `tests/e2e/src/fixtures.ts`**

```ts
import { test as base, expect, type BrowserContext, type Page } from '@playwright/test';

declare global {
  interface Window {
    reportCspViolation: (violation: string) => void;
  }
}

/**
 * Collects the Content-Security-Policy violations of every page in a browser context, across
 * reloads. A violation means the app does something the CSP forbids (ADR 0016).
 */
export async function watchCsp(context: BrowserContext): Promise<string[]> {
  const violations: string[] = [];
  await context.exposeFunction('reportCspViolation', (violation: string) => {
    violations.push(violation);
  });
  await context.addInitScript(() => {
    document.addEventListener('securitypolicyviolation', (event) => {
      window.reportCspViolation(
        `${event.violatedDirective} blocked ${event.blockedURI || 'inline'}`,
      );
    });
  });
  return violations;
}

/** Playwright's `test`, plus: any CSP violation in the test's page fails the test. */
export const test = base.extend<{ cspViolations: string[] }>({
  cspViolations: [
    async ({ context }, use) => {
      const violations = await watchCsp(context);
      await use(violations);
      expect(violations, 'CSP violations').toEqual([]);
    },
    { auto: true },
  ],
});

export { expect };

/** Signs in with the app's own button, as a user would, and waits for the name in the header. */
export async function signIn(page: Page, name = 'Local Developer'): Promise<void> {
  await page.goto('/');
  await page.getByRole('button', { name: 'Sign in' }).click();
  await expect(page.getByRole('banner').getByText(name)).toBeVisible();
}
```

```ts
import { randomUUID } from 'node:crypto';
import type { Page } from '@playwright/test';
import { expect, signIn, test, watchCsp } from './fixtures.js';

// The database is shared by every test and by manual testing, so each test only looks for notes it
// created itself, by a unique title.
function uniqueTitle(label: string): string {
  return `${label} ${randomUUID().slice(0, 8)}`;
}

async function addNote(page: Page, title: string): Promise<void> {
  await page.getByLabel('Title').fill(title);
  await page.getByLabel('Body').fill('Written by Playwright');
  await page.getByRole('button', { name: 'Add note' }).click();
  await expect(notes(page).getByText(title)).toBeVisible();
}

function notes(page: Page) {
  return page.getByRole('list', { name: 'Notes' });
}

test('a note survives a reload and can be deleted', async ({ page }) => {
  const title = uniqueTitle('E2E note');
  await signIn(page);
  await addNote(page, title);

  await page.reload();
  await expect(notes(page).getByText(title)).toBeVisible();

  await page.getByRole('button', { name: `Delete ${title}` }).click();
  await expect(page.getByText(title)).toHaveCount(0);
});

test('users see only their own notes', async ({ page, browser }) => {
  const mine = uniqueTitle('First user note');
  const theirs = uniqueTitle('Second user note');
  await signIn(page);
  await addNote(page, mine);

  // A second browser session, signed in as the mock's second test user (ADR 0009). The app asks
  // the mock for a token with the clientId from /config.json, so the test changes that value.
  const other = await browser.newContext();
  const otherViolations = await watchCsp(other);
  const otherPage = await other.newPage();
  await otherPage.route('/config.json', async (route) => {
    const response = await route.fetch();
    const config = (await response.json()) as { auth: { clientId: string } };
    config.auth.clientId = 'atlas-e2e-second-user';
    await route.fulfill({ response, json: config });
  });
  await signIn(otherPage, 'Second User');
  await addNote(otherPage, theirs);
  await expect(otherPage.getByText(mine)).toHaveCount(0);

  await page.reload();
  await expect(notes(page).getByText(mine)).toBeVisible();
  await expect(page.getByText(theirs)).toHaveCount(0);

  // Clean up, as each user.
  await page.getByRole('button', { name: `Delete ${mine}` }).click();
  await otherPage.getByRole('button', { name: `Delete ${theirs}` }).click();
  await expect(otherPage.getByText(theirs)).toHaveCount(0);
  await other.close();
  expect(otherViolations, 'CSP violations (second user)').toEqual([]);
});
```

    - uses: actions/checkout@v7

    # cache takes about as long, and the system packages the browser needs can't be cached.
    - name: Install Chromium

    - run: npm run test:e2e

    - name: Container logs
      if: failure()
      run: docker compose --profile full logs

    - name: Upload the Playwright report
      if: failure()
      uses: actions/upload-artifact@v7
      with:
        name: playwright-report
        path: tests/e2e/playwright-report
        retention-days: 7

```markdown
# 0009. Mock OIDC for end-to-end tests, with the issuer guard

- **Status:** Accepted
- **Date:** 2026-10-17

## Context

- **End-to-end tests have to sign in.** Real Entra ID would need test users exempt from MFA. We can't create those in the university tenant, and automated tests can't do MFA.
- **The mock OIDC server** (`ghcr.io/navikt/mock-oauth2-server` in `compose.yaml`) issues signed tokens shaped like Entra's (`iss`, `aud`, `scp`, `oid`, `tid`, `name`). The web app's `mock` sign-in kind asks it for tokens directly (ADR 0007).
- **The tests need at least two users,** to prove that one can't see the other's notes.
- **In compose, the mock has two addresses.** The browser reaches it as `localhost:8090`, so tokens carry that issuer. The API container reaches it as `mock-oidc:8080`.

## Decision

- **Playwright tests (`tests/e2e`) run against the compose `full` stack with `ATLAS_ENV=ci`.** The API trusts the mock only because of that: its issuer guard refuses a non-Entra issuer in dev, UAT and prod.
- **Two test users in `dev/mock-oidc/config.json`, picked by the token request's `client_id`:**
  - `atlas-e2e-second-user` gets "Second User"
  - anything else gets "Local Developer", the default for development and the first test user

  The mock uses the first mapping that matches, so the second user's mapping comes first.

- **A test signs in as the second user by changing `auth.clientId` in `/config.json`** for its browser context (a Playwright route). The sign-in code is the app's own; nothing test-only ships in the bundle.
- **The API checks the token's `iss` against `http://localhost:8090/atlas`** and fetches the keys from `OIDC_JWKS_URI=http://mock-oidc:8080/atlas/jwks`.
- **Playwright runs on the host and the CI runner, not in a container,** so the browser uses the same addresses as a developer. Chromium only, for now.
- **A CSP violation fails any test** (ADR 0016).

## Consequences

- **The tests cover our whole path:** UI, nginx, the API's token validation, the database and ownership. They don't cover Entra itself. MSAL is exercised against real Entra in deployed environments (the M5 sign-in check).
- **A company would add Entra-backed E2E tests in UAT,** with a dedicated test user excluded from MFA by conditional access, and keep this mock suite on every pull request.
- **The mock's signing keys are generated when it starts,** so its tokens are worthless anywhere else.
- **A role-based scenario later means another mock user** with a `roles` claim.
```
