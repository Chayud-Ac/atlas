# M6: UAT and prod Implementation Plan

> **How this plan was executed:** as with M5, Claude checked the subscription first (read-only), then built and ran everything. The user had approved the cost and the regions. The two approvals in the first promotion are clicked by the user. This file is mostly a record; the code is in the PR.

**Goal:** A merge to `main` deploys one image to dev, then promotes **the same SHA** to UAT and prod after approval, and ends with a GitHub Release (spec §3.2). UAT and prod have private Postgres networking, prod keeps a warm replica and a delete lock, and nobody has database access in UAT or prod by default.

**Architecture:**

- **Two more environments,** each in its own region (ADR 0017): `rg-atlas-uat` in `malaysiawest` and `rg-atlas-prod` in `japanwest`. Each has the same platform as dev, except that Postgres is VNet-integrated with a private DNS zone (ADR 0008).
- **`deploy.yml` runs dev → uat → prod → release.** UAT and prod reuse `deploy-env.yml`, and their GitHub environments require the repo owner's approval.
- **`bootstrap.sh` reads per-environment flags from `environments.json`:** `requiresApproval`, `deleteLock`, `humanDbAccess` and `localhostRedirect`. It hard-codes no environment names.

## Decisions

- **UAT in `malaysiawest`, prod in `japanwest`.** It's the reverse of what was first suggested: the newest region, which still lacks some APIs, takes the less critical environment.
- **Cost:** about $1.70 a day more. That's two more Postgres B1ms servers, and prod's minimum of one replica per app.

## Deviations from the spec

1. **Different regions per environment** (ADR 0017), forced by the quota.
2. **Prod alerts, availability tests and `ALERT_EMAIL` wait for M7,** with the rest of observability.
